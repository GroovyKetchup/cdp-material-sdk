# 引擎基础能力模型

引擎基础能力是宿主自动赋予所有组件的通用运行时能力。组件作者一般不需要在 manifest 中重复声明这些能力——它们由宿主统一注入，重复声明会**覆盖**宿主版本，破坏对外行为的一致性。仅当组件**确有特化需求**时，才建议显式声明覆盖。

---

## 基础能力总览

| 能力 | 外部含义 | 组件作者需要做什么 |
|------|----------|-------------------|
| `hidden` prop | 宿主告诉组件当前是否隐藏 | 可按需读取；不建议改写为其他业务语义 |
| `getHidden` action | 外部流程读取组件显隐状态 | 默认不声明；如需特化（例如不同的 returns 描述）再显式覆盖 |
| `setHidden` action | 外部流程设置组件显隐状态 | 默认不声明；如需特化再显式覆盖 |
| `toggleHidden` action | 外部流程切换组件显隐状态 | 默认不声明；如需特化再显式覆盖 |
| `hidden` state | 外部表达式、编排或 AI 读取当前显隐状态 | 默认不声明；如需特化 schema 再显式覆盖 |
| `mount` / `unmount` events | 基础生命周期通知 | 默认不声明；普通组件无需重复 |

> 显式声明同名字段会覆盖宿主默认版本，请确认特化是必要的，并在 review 时让上游能识别这是有意覆盖。

---

## 与组件 manifest 的关系

基础能力由宿主在运行时补充。第三方组件 manifest 通常只需声明组件自己的业务能力，例如：

- 业务 actions，例如 `refresh`、`clear`、`focus`。
- 业务 state，例如 `selectedRows`、`keyword`。
- 业务 events，例如 `valueChange`、`itemClick` 或自定义事件。

一般不需要为了获得显隐控制而在 manifest 中手写 `getHidden`、`setHidden`、`toggleHidden` 或 `hidden` state；只在确有特化需求时再覆盖。

---

## 与 DOM 根节点注入的关系

基础能力中的显隐、选中、定位等能力需要和组件真实 DOM 对齐。组件作者不需要关心宿主内部使用了哪些 DOM 标记，只需要确认：

- 组件声明了合适的 `engine.render.injection.rootPath`。
- rootPath 指向的 props 最终展开到了真实 DOM 节点。
- 设计器选中、显隐控制和组件视觉区域一致。

具体配置方式见 [DOM 根节点注入模型](./DOM根节点注入模型.md) 和 [配置 DOM 根节点注入](../recipes/配置DOM根节点注入.md)。
