# 配置设计器元信息

`meta` 中的几个字段决定组件在设计器物料面板里如何被找到、如何被分组、是否可见。它们不影响运行时渲染，但直接影响设计器使用体验和 AI 工具识别。

---

## 适用场景

- 组件需要更友好的图标或显示名。
- 组件应该归到分类下的某个子分组。
- 组件是某个父组件的内部部件，不应单独出现在物料面板。

---

## 可以跳过的情况

- 组件用默认分类、不需要图标、希望直接出现在物料面板。
- 组件还在最小实现阶段，先按 [03-开发最小可运行组件](../getting-started/03-开发最小可运行组件.md) 跑通再回来配置。

---

## 字段总览

| 字段 | 类型 | 默认 | 影响 |
|------|------|------|------|
| `meta.title` | `string` | 必填 | 物料面板显示名、设计器节点名 |
| `meta.description` | `string` | 无 | 物料面板 Tooltip、AI 工具理解组件用途 |
| `meta.category` | `ComponentCategory` | 必填 | 物料面板顶层分类 |
| `meta.subGroup` | `string` | 无 | 在 `category` 下进一步分组 |
| `meta.icon` | `string` | 无 | 物料面板图标、设计器节点图标 |
| `meta.hiddenInComponentList` | `boolean` | `false` | 是否在物料面板中隐藏 |

---

## 配置示例

```ts
import {
  COMPONENT_CATEGORY,
  type ComponentManifest,
} from 'cdp-material-sdk/portable';

export const acmeAvatarManifest = {
  type: 'acme.Avatar',
  meta: {
    title: '头像',
    description: '用于展示用户头像、首字母或占位图',
    category: COMPONENT_CATEGORY.DATA_DISPLAY,
    subGroup: '用户信息',
    icon: 'user-circle',
  },
  // ...
} satisfies ComponentManifest;
```

---

## icon

`meta.icon` 是字符串，具体含义由设计器决定。常见约定：

- 设计器内置图标库的图标名（例如 `user-circle`、`table-2`）。
- 组件包随附的 SVG 资源标识（如 `acme://icons/avatar`）。
- 远程图标 URL（部分设计器支持）。

经验法则：

- 优先使用设计器内置图标库，跨组件保持视觉一致。
- 不写就会用分类的默认图标，作者在最小实现阶段可以先不填。
- 不要把业务态图标（如「在线 / 离线」）放进 `icon`，那是组件运行时的渲染范围。

---

## subGroup

`subGroup` 在 `category` 之下做二次分组，物料面板会把同一 `subGroup` 的组件聚合显示。

| 用法 | 示例 |
|------|------|
| 同分类下的功能子集 | `category: DATA_ENTRY`、`subGroup: '日期时间'` |
| 同源组件聚合 | `category: DATA_DISPLAY`、`subGroup: '用户信息'` |
| 业务领域聚合 | `category: GENERAL`、`subGroup: '工作流'` |

经验法则：

- 同包内尽量复用相同的 `subGroup` 字符串，避免出现「日期时间」「日期 / 时间」「日期类」这种近义但不同的分组。
- 跨包的 `subGroup` 由设计器决定是否合并展示，不要依赖跨包合并行为。

---

## hiddenInComponentList

声明 `hiddenInComponentList: true` 后，组件不会出现在物料面板，但仍可以：

- 通过父组件的 `slots.allowedChildren` 或 `nesting.allowedChildren` 被自动加入。
- 被设计器复制粘贴、撤销恢复。
- 在运行时渲染。

典型场景：

- **父子绑定的子部件**：例如 `acme.TabPane`、`acme.StepItem`、`acme.TableColumn`，必须在父容器里使用，不应单独拖入。
- **内部辅助组件**：例如某个仅在 wrapper 中使用的中间层组件。
- **过渡期废弃组件**：保持 `type` 兼容性，但不希望新页面再使用。

经验法则：

- 子部件类组件几乎都应该 `hiddenInComponentList: true`，并通过父组件的 `nesting` / `slots` 暴露入口。
- 不要用 `hiddenInComponentList` 来"软删除"组件——保留 manifest 但不可见会让维护者困惑。彻底废弃应通过版本号或 `alias` 标记。

---

## 自检

- [ ] `meta.title` 与 `meta.description` 都是面向使用者的可读文案。
- [ ] `meta.category` 选择合适的顶层分类。
- [ ] 同包内 `subGroup` 字符串保持一致。
- [ ] `meta.icon` 引用设计器或组件包能够解析的标识。
- [ ] 子部件类组件已声明 `hiddenInComponentList: true`，并由父组件通过 `nesting` / `slots` 暴露。
- [ ] `validateManifest()` 没有 error。

---

## 常见错误

### 用 hiddenInComponentList 隐藏未实现的组件

物料面板看不到，但 manifest 仍会被加载、校验。请直接不导出该组件，或用包级开关控制。

### 在 title 里塞业务前缀

`meta.title` 是物料面板的显示名，建议简洁可读（"头像"、"日期选择"）。业务来源信息可以放进 `description`，或通过 `subGroup` 分组。

### subGroup 写得太散

每写一次新的 `subGroup` 字符串，物料面板就会多一个分组。同一类组件若要聚合，请在包内复用同一个常量。
