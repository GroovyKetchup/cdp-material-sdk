# 声明插槽

插槽用于让组件提供可被设计器填充的区域，例如卡片内容区、表格列模板、列表项模板等。

---

## 适用场景

- 组件需要承载子组件。
- 组件有固定区域允许业务方拖入内容。
- 组件需要按数据行渲染模板。

---

## 可以跳过的情况

- 组件不承载子组件。
- 组件只通过 props 配置内容。
- 组件只是一个单一输入或展示控件。

---

## 命名插槽

最常见，也最推荐第三方作者优先使用。

```ts
slots: {
  header: {
    title: '头部',
    description: '卡片头部内容',
  },
  body: {
    title: '内容',
    description: '卡片主体内容',
  },
}
```

组件通过宿主注入的 `_slots` 消费：

```tsx
export function Card(props: any) {
  const { _slots } = props;

  return (
    <section>
      <header>{_slots?.header}</header>
      <main>{_slots?.body}</main>
    </section>
  );
}
```

---

## 作用域插槽

适合表格行、列表项这类需要向子内容提供上下文的场景。

```ts
slots: {
  rowActions: {
    title: '行操作',
    scoped: true,
    scopeDescription: '提供当前行 record 和 rowIndex',
  },
}
```

`scopeDescription` 不是强制字段，但建议声明，方便设计器和 AI 理解上下文。

---

## 动态插槽

适合根据 props 数组生成多个插槽，例如表格列模板。

```ts
slots: {
  columnSlot: {
    title: '列模板',
    dynamic: true,
    dynamicSource: 'columns',
    dynamicKey: 'col:{dataIndex}',
    dynamicTitle: '列：{title}',
    scoped: true,
    scopeDescription: '提供当前行 record',
  },
}
```

动态插槽必须声明：

- `dynamicSource`
- `dynamicKey`

---

## 自检

- [ ] 每个 slot 都有 `title`。
- [ ] 动态 slot 声明了 `dynamicSource` 和 `dynamicKey`。
- [ ] 作用域 slot 建议声明 `scopeDescription`。
- [ ] `allowedChildren` 如果声明，必须是字符串数组。
- [ ] 组件实际渲染了 `_slots` 或 `_scopedSlots`。
- [ ] `validateManifest()` 没有 error。

---

## 常见错误

### 声明了 slot，但组件没有渲染

设计器会显示插槽，但运行时不会看到内容。请确认组件消费了对应 `_slots[name]`。

### 动态 slot 缺少 dynamicKey

宿主无法生成稳定 slot 名称，`validateManifest()` 会报错。

### 把多个固定区域都塞进默认 children

`LAYOUT_CONTAINER` 只控制**默认 children 区域**的开关，与 `slots` 是两条独立机制。如果组件有 header / footer / extra 等多个固定区域，应声明 `slots` 让宿主分别注入到 `_slots[name]`，不要把它们都挤进 `children`，否则设计器和 AI 工具会失去结构信息。

只用 slots 接子内容的组件**不需要**声明 `LAYOUT_CONTAINER` trait。
