# 04 - 构建发布与宿主接入

本文说明组件包如何构建成宿主可加载的 ESM 插件，以及交付时需要提供哪些信息。

---

## 适用场景

- 你已经完成组件和 `EngineComponentPlugin`。
- 你要将组件包交付给 CDP 宿主加载。
- 你要确认 bundle 依赖处理是否正确。

---

## 构建目标

宿主期望加载一个 ESM 模块。该模块应导出 `EngineComponentPlugin`，通常使用 default export：

```ts
import type { EngineComponentPlugin } from 'cdp-material-sdk/portable';
import { myPackage } from './package';

const plugin: EngineComponentPlugin = {
  id: myPackage.id,
  version: myPackage.version,
  install: (api) => {
    api.registerPackage(myPackage);
  },
};

export default plugin;
```

---

## Vite 构建配置

```ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import dts from 'vite-plugin-dts';

export default defineConfig({
  plugins: [react(), dts()],
  build: {
    lib: {
      entry: 'src/plugin.ts',
      formats: ['es'],
      fileName: 'index',
    },
    rollupOptions: {
      external: ['react', 'react/jsx-runtime', 'react-dom'],
    },
  },
});
```

---

## 依赖处理

| 依赖 | 推荐处理 |
|------|----------|
| `react` | `peerDependencies` + externalize，由宿主提供 |
| `react-dom` | `peerDependencies` + externalize，由宿主提供 |
| `react/jsx-runtime` | externalize |
| `cdp-material-sdk/portable` | 可作为普通依赖使用 |
| `cdp-material-sdk/host-react` | 仅当确认共享宿主 React Context 时使用 |
| UI 组件库 | 默认打入 bundle；如需共享，需与宿主协商 externalize |

---

## 交付给宿主的信息

正式交付时，至少提供：

| 信息 | 示例 |
|------|------|
| 组件包 id | `@acme/cdp-components` |
| 版本 | `1.0.0` |
| ESM URL | `/packages/acme-cdp-components/index.js` |
| integrity | `sha384-...` |
| 组件清单 | `acme.MyText`、`acme.UserCard` |
| SDK 版本 | `cdp-material-sdk@0.0.4` |

后端下发字段由宿主侧契约决定，通常包含 `id`、`version`、`url`、`integrity`。

---

## Build Checklist

- [ ] `npm run build` 能成功输出 ESM。
- [ ] 入口文件默认导出 `EngineComponentPlugin`。
- [ ] `react`、`react-dom`、`react/jsx-runtime` 没有打进 bundle。
- [ ] `EngineComponentPlugin.id` 与 `EngineComponentPackage.id` 一致。
- [ ] `EngineComponentPlugin.version` 与 `EngineComponentPackage.version` 一致。
- [ ] 每个组件的 `manifest.type` 唯一且稳定。
- [ ] 每个 manifest 通过 `validateManifest()`。
- [ ] 如果使用 `host-react`，已确认外部 bundle 与宿主共享同一份 React runtime 和 Context 身份。

## 交付模式对比

| 模式 | 适用阶段 | 说明 |
|------|----------|------|
| 同源 URL 直载 | 联调、灰度、内部验证 | 宿主通过 URL 动态导入 ESM |
| 独立 npm / tgz 包 | 正式交付、版本管理 | 独立仓库构建后发布产物 |
| 文档内模板 | 快速复制、理解 authoring 方式 | 以本文和 [示例代码索引](../reference/示例代码索引.md) 为准 |

## 常见错误

### 把 React 打进 bundle

现象：组件渲染、Context 或 ref 行为异常。

处理：检查构建产物和 `rollupOptions.external`，确保 `react`、`react-dom`、`react/jsx-runtime` 被 externalize。

### 插件没有 default export

现象：宿主动态导入模块后无法解析插件。

处理：确保入口文件 `export default plugin`。

### 修改了已有组件 type

现象：旧页面或旧 DSL 找不到组件。

处理：`type` 是稳定协议。重命名应作为破坏性变更处理，并提供迁移方案。
