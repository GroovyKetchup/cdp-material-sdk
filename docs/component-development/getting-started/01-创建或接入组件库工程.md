# 01 - 创建或接入组件库工程

本文说明如何准备一个可交付给 CDP 宿主加载的组件库工程。

这一步是**建议流程**，不是强制流程。CDP 真正关心的是最终产物：一个可被动态导入的 ESM 插件，以及其中注册的 `EngineComponentPackage`。

---

## 适用场景

- 你要从零创建一个第三方组件包工程。
- 你已有 UI 组件库，希望新增一个 CDP 适配层。
- 你在团队内维护一个长期演进的组件包。

如果你已经有组件包工程，并且只是新增组件，可以直接阅读 [开发最小可运行组件](./03-开发最小可运行组件.md)。

---

## 推荐目录结构

```text
my-cdp-components/
├── src/
│   ├── components/
│   │   └── MyButton/
│   │       ├── index.tsx
│   │       └── manifest.ts
│   ├── manifests.ts
│   └── plugin.ts
├── package.json
├── tsconfig.json
├── vite.config.ts
└── README.md
```

目录说明：

| 路径 | 职责 |
|------|------|
| `src/components/*/index.tsx` | React 组件或第三方组件 wrapper |
| `src/components/*/manifest.ts` | 单组件的 `ComponentManifest` |
| `src/manifests.ts` | 汇总组件注册项，便于团队协作审查 |
| `src/plugin.ts` | 导出 `EngineComponentPlugin`，宿主加载入口 |
| `vite.config.ts` | 将插件构建为 ESM library |

## 安装 SDK

推荐从 npm 安装最新版：

```bash
npm install cdp-material-sdk@latest react react-dom
```

如需锁定到精确版本：

```bash
npm install cdp-material-sdk@<version> react react-dom
```

无 npm 访问时，可回退到 GitHub Release `.tgz`：

```bash
npm install https://github.com/GroovyKetchup/cdp-material-sdk/releases/download/v<version>/cdp-material-sdk-<version>.tgz
```

`react` 与 `react-dom` 是 peer dependency，需要由组件作者侧显式安装（建议 19.x）。

默认导入入口：

```ts
import type { ComponentManifest, EngineComponentPlugin } from 'cdp-material-sdk/portable';
```

导入边界：

| 入口 | 用途 |
|------|------|
| `cdp-material-sdk/portable` | 默认入口。用于声明 manifest、组件包、插件、traits、校验工具 |
| `cdp-material-sdk/host-react` | 仅在确认与宿主共享 React runtime 和 Context 身份时使用 |

## package.json 关键约束

```jsonc
{
  "name": "@myorg/cdp-components",
  "version": "1.0.0",
  "type": "module",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "peerDependencies": {
    "react": "^19.1.1",
    "react-dom": "^19.1.1"
  },
  "dependencies": {
    "cdp-material-sdk": "<tgz-url-or-version>"
  }
}
```

关键点：

- **不要把 React 打进 bundle。** `react`、`react-dom`、`react/jsx-runtime` 应由宿主提供。
- `cdp-material-sdk/portable` 可以作为依赖使用。
- UI 组件库是否 externalize 需要与宿主协商；默认可以打入 bundle。

## Vite library mode 参考

```ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import dts from 'vite-plugin-dts';

export default defineConfig({
  plugins: [react(), dts()],
  build: {
    lib: {
      entry: 'src/plugin.ts',
      formats: ['es'],
      fileName: 'index',
    },
    rollupOptions: {
      external: ['react', 'react/jsx-runtime', 'react-dom'],
    },
  },
});
```

## 团队协作建议

如果组件包由多人维护，建议约定：

- 每个组件独立目录，组件实现和 manifest 放在一起。
- 组件 `type` 使用命名空间，例如 `acme.Button`、`acme.UserCard`。
- 新增组件只修改自己的目录和组件注册清单。
- 每次新增组件都运行 [自检与排错](./05-自检与排错.md)。
- 不直接依赖宿主源码路径或未从 `cdp-material-sdk` 公开入口导出的模块。

---

## 完成标准

- [ ] 工程可以执行 `npm run build`。
- [ ] 构建产物是 ESM。
- [ ] React 相关依赖没有被打入 bundle。
- [ ] 工程中只从 `cdp-material-sdk/portable` 或必要的 `host-react` 入口导入 SDK API。
- [ ] 已准备 `src/plugin.ts` 作为宿主加载入口。
