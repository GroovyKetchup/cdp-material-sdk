# 05 - 自检与排错

本文说明组件作者如何在交付前自检 manifest、组件 ref 契约、根节点注入和打包产物。

---

## 适用场景

- 新增或修改组件后，需要确认契约是否正确。
- 组件已经接入宿主，但渲染、事件、动作或状态不生效。
- 构建后的组件包需要交付给宿主。

---

## 1. Manifest 静态校验

`cdp-material-sdk/portable` 提供纯函数校验工具：

```ts
import {
  validateManifest,
  printValidationResult,
} from 'cdp-material-sdk/portable';
import { myManifest } from './components/MyComponent/manifest';

const result = validateManifest(myManifest);
printValidationResult(result);

if (!result.valid) {
  process.exitCode = 1;
}
```

批量校验：

```ts
import {
  validateManifests,
  printValidationResult,
} from 'cdp-material-sdk/portable';
import { myPackage } from './package';

const result = validateManifests(
  myPackage.components.map((item) => item.manifest),
);

printValidationResult(result);

if (!result.valid) {
  process.exitCode = 1;
}
```

建议在组件包工程中提供脚本：

```jsonc
{
  "scripts": {
    "validate:manifest": "tsx scripts/validate-manifests.ts"
  }
}
```

## 2. Actions / State 运行时诊断

如果组件声明了 `actions` 或 `state`，还需要确认 ref 实际暴露了对应能力。

```ts
import {
  COMPONENT_STATE_KEY,
  diagnoseMissingActionImpls,
  diagnoseMissingStateKeys,
} from 'cdp-material-sdk/portable';

const refValue = ref.current;

const missingActions = diagnoseMissingActionImpls(
  Object.keys(myManifest.actions ?? {}),
  refValue,
);

const missingStateKeys = diagnoseMissingStateKeys(
  myManifest,
  refValue?.[COMPONENT_STATE_KEY],
);
```

如果 `missingActions` 或 `missingStateKeys` 非空，说明 manifest 声明和组件实现不一致。

## 3. rootPath 注入自检

检查组件根节点是否拿到宿主注入属性：

- `data-id`
- `data-path`
- `data-engine-hidden`

推荐写法：

```tsx
<div {...slotProps?.root}>...</div>
```

对应 manifest：

```ts
import { INJECT_PATH_SLOT_PROPS } from 'cdp-material-sdk/portable';

engine: {
  render: {
    injection: {
      rootPath: INJECT_PATH_SLOT_PROPS,
    },
  },
},
```

如果你使用自定义 `rootPath`，请确认该路径上的 props 最终透传到了真实 DOM 根节点。

---

## 4. 打包自检

构建后检查：

- [ ] 产物是 ESM。
- [ ] `react`、`react-dom`、`react/jsx-runtime` 已 externalize。
- [ ] 入口模块能解析出 `EngineComponentPlugin`。
- [ ] `plugin.install(api)` 调用了 `api.registerPackage(pkg)`。
- [ ] `pkg.components` 包含所有对外组件。
- [ ] 没有从宿主源码路径或未公开的内部模块导入。

---

## 5. 常见现象与处理

| 现象 | 优先检查 |
|------|----------|
| 组件能渲染，但设计器无法选中 | `rootPath` 是否声明并透传到真实 DOM |
| Action 调用无效 | manifest `actions` 和 `useImperativeHandle` 暴露方法是否一致 |
| State 表达式读不到 | 是否使用 `COMPONENT_STATE_KEY` 暴露状态 |
| 自定义事件不触发 | `customEvents` 是否声明，`adapter.customEvents` 是否引用同一事件名 |
| Loading 不生效 | `engine.render.loading.strategy` 是否符合组件实际能力 |
| 表单值不更新 | 是否声明 `DATA_FIELD`，组件是否接收 `value` 并调用 `onChange` |
| 容器内字段写错位置 | 数据容器是否正确建立 DataScope，字段是否有 `name` |

---

## 6. Error 与 Warning 的处理原则

| 级别 | 处理建议 |
|------|----------|
| error | 必须修复，否则不应交付 |
| warning | 需要确认是否符合预期；如果已按规则实现，可以记录并接受 |

例如自定义 `rootPath` 会提示作者确认 props 是否透传到根 DOM。若组件已经按规则实现，可忽略该提示。
